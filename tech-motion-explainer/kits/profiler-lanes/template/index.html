설명 읽기용어집

60Hz 화면에서 브라우저는 16.7ms마다 새 프레임을 낼 기회가 있다. 메인 스레드에서 55ms짜리 작업 하나가 돌면, 그동안 메인 스레드가 맡아야 하는 프레임은 나오지 못하고 세 번의 기회를 놓친다. 화면의 시간 수치는 예시다.

네 줄의 타임라인은 위에서부터 메인 스레드, 컴포지터, 래스터, GPU다. 세로로 선 판은 16.7ms마다 오는 vsync, 즉 프레임 마감이다.

평소 프레임에서는 메인 스레드가 스크립트, 스타일, 레이아웃, 페인트를 9.5ms 안에 끝내고, 컴포지터가 커밋을 받아 래스터와 GPU로 넘긴다. 다음 마감 전에 끝나므로 판은 흰색으로 남는다.

두 번째 프레임 작업이 끝난 직후 메인 스레드에서 55ms짜리 작업이 시작된다. 그동안 스타일, 레이아웃, 페인트가 돌지 못해 새 커밋이 없고, 래스터는 커밋을 기다린다. 메인 스레드가 그려야 하는 프레임 마감 세 번이 지나가고 그 판이 빨갛게 바뀐다.

컴포지터만으로 되는 스크롤과 transform 애니메이션은 이 동안에도 프레임을 낸다. 긴 작업을 50ms 아래 조각으로 나누면 메인 스레드도 마감 사이에 프레임을 끼워 넣을 수 있다.

용어 정리

vsync
화면이 새 프레임을 받는 주기. 60Hz면 16.7ms마다 온다.
메인 스레드
스크립트 실행, 스타일 계산, 레이아웃, 페인트 기록을 하는 브라우저 스레드.
컴포지터
메인 스레드가 넘긴 레이어를 받아 프레임을 조립하는 스레드. 스크롤과 transform 애니메이션은 혼자서도 처리한다.
커밋
메인 스레드가 만든 결과를 컴포지터로 넘기는 단계.
래스터
페인트 기록을 실제 픽셀 타일로 바꾸는 작업.
긴 작업 (long task)
메인 스레드를 50ms 넘게 붙잡는 작업. 그동안 입력 처리와 프레임이 밀린다.
