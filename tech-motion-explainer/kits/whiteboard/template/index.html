설명 읽기용어집

브라우저는 이름이 아니라 IP 주소로 접속합니다. 주소창에 example.com을 치면 먼저 그 이름의 IP 주소를 찾아야 하고, 이 과정이 DNS 조회입니다. 가까운 캐시에 답이 없을 때만 리졸버가 루트 → TLD → 권한 서버를 차례로 묻고, 받은 답은 TTL 동안 캐시에 남아 다음 조회를 바로 끝냅니다.

브라우저는 먼저 자기 DNS 캐시를, 그다음 운영체제의 캐시(와 hosts 파일)를 봅니다. 화면의 예시는 둘 다 비어 있는 경우입니다.

둘 다 없으면 OS의 스텁 리졸버가 설정된 재귀 리졸버(ISP, 회사, 또는 공용 DNS)에 이름을 묻습니다. 여기서부터 답을 찾는 일은 리졸버가 맡습니다.

리졸버의 캐시에도 답이 없으면, 리졸버는 서버를 차례로 묻습니다(반복 질의).

  • 루트 서버: .com을 맡은 TLD 서버 목록을 알려 줍니다.
  • .com TLD 서버: example.com을 맡은 권한 서버 목록을 알려 줍니다.
  • 권한 서버: A 레코드(IP 주소)와 TTL로 답합니다.

리졸버는 이 답을 브라우저 쪽에 돌려줍니다. 화면의 203.0.113.10은 문서용 예시 주소이고 TTL 300초도 예시입니다. 실제로는 TLD 서버 목록 같은 위임 정보도 리졸버 캐시에 오래 남아 있어서, 매번 루트까지 가지는 않습니다.

리졸버는 받은 답을 TTL 동안 캐시에 둡니다. 그동안 같은 이름을 묻는 다음 조회는 서버를 거치지 않고 리졸버 캐시에서 바로 끝납니다. 브라우저와 OS 캐시도 같은 답을 일정 시간 보관합니다.

TTL이 지나면 캐시가 지워지고, 다음 조회는 다시 02의 과정을 거칩니다. 주소를 바꿀 계획이 있으면 TTL을 미리 짧게 줄여 두는 이유가 이것입니다.

용어 정리

DNS
이름(example.com)을 IP 주소로 바꿔 주는 분산 이름 체계.
스텁 리졸버
OS에 들어 있는 작은 DNS 클라이언트. 직접 찾지 않고 재귀 리졸버에게 묻는다.
재귀 리졸버
클라이언트 대신 서버들을 차례로 물어 최종 답을 찾아 주는 DNS 서버. ISP, 회사, 공용 DNS가 운영한다.
루트 서버
DNS 계층의 맨 위. 각 TLD를 맡은 서버를 알려 준다.
TLD 서버
.com, .kr 같은 최상위 도메인을 맡은 서버. 그 아래 도메인의 권한 서버를 알려 준다.
권한 서버
한 도메인의 레코드를 실제로 가지고 있는 서버. 최종 답을 준다.
A 레코드
이름에 대응하는 IPv4 주소를 담은 레코드.
TTL
답을 캐시에 둘 수 있는 시간(초). 레코드마다 권한 서버가 정한다.
캐시 HIT
캐시에 답이 있어 더 묻지 않고 끝나는 경우.
