# Translating the film (one set of scenes, every language)

## How it works
- The scenes are written in the **source language** (`film.json` `"source"`, default `ko`; set `window.FILM_SRC` in each
  scene if it isn't Korean). Every on-screen string is drawn through `Pilot.text` / `Pilot.tr`, which, with `?lang=xx`,
  looks the exact source string up in `scenes/i18n/xx.json` and draws the translation (shrinking it if it overflows).
  The source language does no lookup at all, so it renders exactly as authored.
- Per scene and language: `scenes/i18n/<lang>/<scene>.json` = `{ "exact source string": "translation" }` — keys include
  `\n`, quotes and spacing exactly as drawn. Portrait variants that differ only by line breaks are separate keys.
- `_ui.json` = the player page text (`title, h1, sub, len, home, homeHref, back, legal, play, pause, prev, next, full,
  loading, landscape, portrait, share, copied, shareText, brand, ch:[chapter names]`).
- `_fonts.json` = `{ "serif": "'Noto Serif SC','Songti SC',serif", "sans": "'Noto Sans SC',…" }` — the harness swaps the
  scenes' own faces (`window.FILM_FONTS`) for these; `publish.py` ships those faces subset to the glyphs used.
- `_meta.json` (optional) = e.g. `{ "_dir": "rtl" }`; common RTL codes are detected automatically.
- `node <skill>/scripts/i18n-merge.mjs <lang>` merges the folder into `scenes/i18n/<lang>.json` (what the scenes load).

## Steps per language
1. `node <skill>/scripts/i18n-scan.mjs <source>` → `scenes/i18n/_<source>/<scene>.json`: `ids` (translatable) and `direct`
   (source text drawn without `Pilot.tr` — fix the scene until `direct` is empty; this is a one-time cost per scene).
2. Write the translation files. Three kinds of text:
   - **Quoted texts** (Scripture, literature): verbatim from that language's own official edition — fetched by a tool,
     never translated by you; that edition's names, numbering and wording (e.g. God's name as that Bible prints it).
   - **Text reused from an existing translation** (the website the film comes from): copy that translation exactly.
   - **Film-only labels**: translate the meaning naturally and briefly in the vocabulary of the quoted edition; write a
     literal back-translation of each in your report so a reviewer can check meaning.
3. `node <skill>/scripts/i18n-scan.mjs <lang>` → every scene `complete`, no leaks (source text left on screen).
4. Contact sheets for every scene in both orientations: `node <skill>/scripts/sheets.mjs <lang>` → `out/sheets/<lang>/` —
   look for tofu boxes (font), overflow, collisions, text shrunk too small.
5. **Native review** — a separate agent per language, report-only (brief: `references/review-prompt.md`): verbatim quotes vs the edition, label naturalness and
   theology/terminology, tone, readability, mixed scripts. Fix every HIGH/MED before sharing widely.
6. Poster stills of the title card per language (`poster-h-<lang>.jpg`), then `publish.py`.

## Rules of thumb (from five native reviews)
- A fragment must make sense alone; include the clause the source shows.
- Name the subject (God, etc.) where the language has no honorific verb to imply it.
- Avoid words with a misleading second meaning; use the quoted edition's own terms.
- Chapter names in `_ui.ch` = the on-screen chapter labels.
- `legal` entirely in the target language; never invent a publisher notice.
- Hyphenate a word that must break on a seal/plate (COVE-/NANT).
- RTL: the harness sets `ctx.direction`; scenes with their own text helpers need RTL branches (right-aligned blocks,
  word-wise reveals so joined letters stay joined, no split-off initials). Keep those branches behind
  `Pilot.dir === 'rtl'` so other languages stay byte-identical.
- Parallelise one agent per language; only ONE agent may edit scene code at a time (others write translation files only
  and report needed code changes).
