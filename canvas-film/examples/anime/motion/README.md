## 이번 결과

`../scenes/crossing-motion.html` — 32.4초, 원래 6개 샷과 카메라·열차·빛·효과·한국어 대사 유지. 가로/세로, 재생/정지, 장면 이동, 스크럽, 전체화면, 합성 효과음/음악, 카메라가 고정된 캐릭터 반복 보기.

- Canvas 삼각형 클립의 중복 알파/경계선을 WebGL indexed mesh + premultiplied alpha로 교체했다.
- 고개 yaw/pitch/roll, 어깨 이동, 호흡, 시선, 눈 깜박임, 표정 시점을 연기 트랙으로 분리했다.
- 머리카락은 고개 회전 속도와 열차 바람에 반응하는 고정 시간 간격 스프링을 사용한다. 앞머리/뒷머리/옆머리의 강성과 지연이 다르다.
- 얼굴과 이목구비는 공통 고개 변형에 작은 깊이 차만 더한다. 목 접합부는 고정해 머리가 떨어지는 것을 줄인다.
- 표정별 알파 범위의 합집합을 렌더링한다. 기존 neutral bbox만 쓰면 sad 입이 잘리던 문제를 수정했다. 미소 중 깜박여도 입이 놀란 표정으로 돌아가지 않는다.
- 전신은 발을 고정한 체중 이동과 열차 바람 반응을 추가했다. 기존 완성 원화 범위 안에서 옷을 움직인다.
- 매 프레임 전체 화면을 지워, 임의 순서 seek에서 이전 프레임이 가장자리에 남는 문제를 없앴다.

## 실행과 단일 HTML

```bash
# 저장소 루트
python3 -m http.server 8000
# /canvas-film/examples/anime/scenes/crossing-motion.html
# 세로 ?o=v / 가로 ?o=h / 렌더 전용 ?render=1&o=h

node canvas-film/examples/anime/motion/build.mjs
# canvas-film/examples/anime/out/summer-crossing-motion.html
# 원화·폰트·코드·사운드 합성기를 모두 포함. 파일 자체를 브라우저에서 연다.
```

`window.seek(t)`, `window.DURATION`, `window.__ready` 계약을 유지한다. `window.inspectPuppet(t)`는 카메라/배경을 고정한 연기 검수다. `window.motionPlayer.jump(t)`는 일반 플레이어에서 이동한다.

## 재사용 경계

| 파일 | 역할 | 새 주제에서 할 일 |
|---|---|---|
| `crossing.story.js` | 목적·주제, 샷 시각, 연기 키, 자막 | 새 시나리오와 타이밍 작성 |
| `motion-acting.js` | 트랙 보간, 고정 스텝 스프링, 표정 제어 | 다른 캐릭터의 강성/동작 범위 보정 |
| `motion-mesh.js` | WebGL 메시 렌더러 | 재사용 |
| `motion-layers.js` | 완성 레이어의 고개/몸/머리카락 변형 | 캐릭터별 head/neck/eye 영역 보정 |
| `motion-rig.js` / `motion-cutout.js` | 전신 리그, 조명 합성 | 재사용, 원화에 맞춘 리그 필요 |
| `motion-player.js` / `motion-sound.js` | 플레이어, 이번 작품의 사운드 | 플레이어 재사용, 사운드 큐는 새 작품에 맞춤 |
| `crossing-motion.html` | 건널목 전용 샷 렌더러 | 새 장소/액션용 샷 구현 |
| `build.mjs` | 로컬 의존성을 단일 HTML에 포함 | 새 entry와 assets 경로 지정 |

주제 이름만 바꿔 같은 건널목을 재생하는 것을 새 작품 생성으로 취급하지 않는다. 새 주제는 샷과 필요한 원화부터 새로 설계한다. 캐릭터 종류가 바뀌면 리그 좌표도 검수해야 한다.

## 제작 절차

1. 입력은 `brief.template.json`을 따른다. 목적·대상·주제·전달할 감정·길이를 정한다. 미지정 항목은 합리적인 가정으로 적는다.
2. 먼저 샷마다 인물의 의도/동작/시선/카메라/효과/길이를 적는다. 움직임은 감정과 사건에서 나온다.
3. 캐릭터 기준 원화를 고정한다. 몸, 얼굴, 눈/입, 뒷머리, 앞머리, 옆머리를 가려진 부분까지 포함해 만든다. 한 장을 자른 빈틈을 변형으로 숨기지 않는다.
4. 얼굴 좌표, 목 접점, 몸 기준점, 각 머리카락 뿌리를 등록한다. 모든 표정의 bbox 합집합을 검사한다. 원화의 허용 범위보다 큰 회전은 새 각도 원화를 추가한다.
5. 연기 트랙을 먼저 만들고 관성/바람을 나중에 더한다. 시선 → 머리 → 몸의 시간차를 준다. 전체 프레임을 계속 흔드는 것으로 연기를 대체하지 않는다.
6. 고정 카메라로 캐릭터를 먼저 검수한 뒤 원래 카메라/효과와 결합한다. 가로/세로 및 전환 직전/직후를 본다.
7. 네트워크를 끈 단일 HTML, seek 재현성, 재생 제어, 콘솔, 표정, 발 접지, 목 접합, 레이어 경계 검사를 통과한 파일을 전달한다.

## 현재 한계

실제 Cubism 모델/SDK가 아닌 2.5D 레이어 리그다. 큰 3D 회전, 걷기/달리기/전투, 대사 립싱크, 손 연기는 이 예제에서 구현하지 않았다. 전신은 기존 cut-part 리그이고 근접 얼굴만 완성 레이어를 사용한다. 시선은 눈 영역의 작은 이동으로, 독립된 흰자/홍채 리그는 다음 원화 단계에서 필요하다. WebGL이 없는 브라우저에서는 기존 Canvas 폴백을 쓰므로 경계 품질과 속도가 낮을 수 있다. 모바일 실제 기기의 성능은 별도 측정이 필요하다.

오디오 자동 재생 제한 때문에 소리는 사용자가 `소리 켬`을 눌렀을 때 시작한다. 효과음과 음악은 이 예제용 절차적 합성이다. 전문 성우/음악 녹음은 포함하지 않는다.
