설명 읽기용어집제품 시연 영상글로벌 현황 프로토타입

렉 판정 서비스 Lag Verdict를 소개하는 영상입니다. 렉 신고가 들어오면 사람마다 아는 데이터 소스에서 아는 방식으로 기록을 찾고, 각자의 순서로 조사하고, AI에게 각자 다르게 묻습니다. 그래서 같은 신고에도 결론과 대응이 갈립니다. Lag Verdict는 조사 순서와 기준을 코드로 고정해, 같은 데이터면 누가 실행해도 같은 판정을 내고, 원인을 네트워크 · 인프라 · 게임서버 · 클라이언트 중 한 층으로 나눕니다. 화면의 인물 · 질문 · 답변 · 이름 · 수치는 모두 예시입니다.

"보스 잡을 때 캐릭터가 뚝뚝 끊겨요"라는 신고 하나를 운영 담당 · 서버 개발자 · QA 세 사람이 조사합니다.

  • 운영 담당: 접속 · 핑 대시보드, 유저 신고 게시판, 네트워크 장비 알림 순서로 보고 AI에게 "핑이 튄 것 같은데 네트워크 문제 맞지?"라고 묻습니다. 결론은 네트워크 렉입니다.
  • 서버 개발자: 서버 틱 메트릭, 서버 로그, GC 로그를 보고 "틱이 밀렸는데 GC 때문일까?"라고 묻습니다. 결론은 게임서버 렉이지만 원인은 GC로 짐작합니다.
  • QA: 클라이언트 로그, 재현 영상, 프레임 캡처를 보고 "클라 프레임이 떨어진 거 아닐까?"라고 묻습니다. 결론은 클라이언트 렉입니다.

어떤 데이터를 먼저 보는지, 무엇을 빼먹는지, 질문에 어떤 가정을 담는지에 따라 답이 달라집니다. 결론이 셋으로 갈리면 네트워크팀 호출, GC 튜닝 검토, 클라이언트 재현 테스트처럼 대응도 셋으로 갈립니다.

Lag Verdict는 조사를 코드로 고정합니다. 입력(프로젝트 · 서버 · 캐릭터 · 신고 시각) → 데이터 소스 다섯 곳(client_perf, net_session, server_tick, host_metrics, ops_events) → 확인 항목(클라이언트 → 네트워크 → 게임서버 → 인프라 순서) → 판정의 길이 항상 같습니다.

확인 항목과 기준값도 코드에 있습니다. 영상의 verdict.rules는 예시로, 1초 최대 프레임 50ms 초과, RTT p95 150ms · 손실 1% 초과, 틱 p95 50ms 초과가 10초 이상, 호스트 · DB 경고와 이웃 서버 동시 이상을 각 층의 이상 조건으로 둡니다. 세 사람이 같은 신고로 실행하면 세 번 모두 같은 데이터를 같은 순서로 보고, 같은 판정(게임서버 렉, 21:14:05–21:14:40, 근거 5개)이 나옵니다. 같은 판정이 나오는 조건은 같은 데이터입니다. 기록이 더 쌓이거나 바뀌면 판정도 그에 따라 바뀝니다.

판정은 네트워크 · 인프라 · 게임서버 · 클라이언트 네 층 중 하나이고, 어느 층도 기준을 넘지 않으면 '이상 없음'입니다. 어느 지표가 튀었는지와 누가 같이 느렸는지로 가릅니다.

  • 네트워크: RTT · 손실이 튀고 서버 틱은 정상입니다.
  • 인프라: 호스트 · DB 지표가 튀고, 같은 호스트 · DB를 쓰는 이웃 서버가 함께 느려집니다. 이때 그 서버들의 틱도 같이 밀리므로, 틱만 보고 게임서버로 정하지 않고 호스트 · 이웃 서버를 함께 봅니다.
  • 게임서버: 틱만 예산을 넘고 호스트 · 이웃 서버는 정상입니다. 이번 판정이고, 틱 p95는 210ms, 직전 이벤트는 21:14:03 boss_spawn입니다. 판정은 층과 구간까지 말합니다. 보스 스폰 때 무엇이 틱을 밀었는지(예: 할당이 몰려 생긴 GC)는 그다음 조사입니다.
  • 클라이언트: 프레임만 튀고 RTT · 틱은 정상입니다.

판정에는 원인 층과 함께 구간과 근거가 남아, 같은 리포트를 보고 대응을 정할 수 있습니다.

용어 정리

렉 판정
렉 신고 한 건의 원인을 네트워크 · 인프라 · 게임서버 · 클라이언트 중 한 층으로 정하고(해당 없으면 '이상 없음'), 구간과 근거를 내는 일.
결정론적 분석
같은 입력과 같은 데이터면 항상 같은 결과가 나오는 분석. 조사 순서와 기준이 코드에 고정되어 있어야 한다.
데이터 소스
판정에 쓰는 기록이 쌓이는 곳. 영상에서는 클라이언트 텔레메트리, 세션 · 네트워크 로그, 게임서버 메트릭, 인프라 모니터링, 운영 이벤트.
확인 항목
층마다 정상 · 이상을 가르는 규칙과 기준값. 영상의 기준값은 예시.
유도 질문
답을 가정한 채 묻는 질문. "네트워크 문제 맞지?"처럼 물으면 그 가정에 맞는 근거부터 찾게 된다.
RTT p95
서버까지 왕복 지연 시간을 줄 세웠을 때 95% 지점의 값.
틱
게임서버가 입력을 처리하고 상태를 갱신해 보내는 한 번의 루프. 초당 20틱이면 한 틱의 예산은 50ms.
GC 일시정지
가비지 컬렉션 때문에 프로그램이 잠깐 멈추는 시간. 틱 지연의 한 가지 원인이 될 수 있다.
운영 이벤트
보스 스폰, 자동 저장, 배포처럼 서버에서 일어난 일을 시각과 함께 남긴 기록.
이웃 서버
같은 호스트나 같은 DB를 쓰는 다른 게임서버. 함께 느려졌는지가 인프라 렉을 가리는 단서다.
